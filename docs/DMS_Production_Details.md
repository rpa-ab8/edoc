### Deviation from the guide: `deploy` has no password

Guide 3.3 creates `deploy` with a password used for `sudo`. Here `deploy` has a **locked password** and **passwordless sudo** (`/etc/sudoers.d/90-deploy-user`). Reason: the account can only be reached with the SSH key, and a member of the `docker` group is root-equivalent anyway, so a sudo password adds almost nothing. To go back to the guide's way: `sudo passwd deploy`, then delete `/etc/sudoers.d/90-deploy-user`.

Worth doing later: put a passphrase on the SSH key (`ssh-keygen -p -f ~/.ssh/digitalocean`), since anyone who copies that file can log in.

## 7. Things the guide didn't say (all folded into the guide, the Data Protection doc and the developer runbook on 2026-11-14)

1. **Logging in from this PC needs `-i ~/.ssh/digitalocean`**: the droplet key is not the default `id_ed25519`. An alias in `~/.ssh/config` avoids typing it.
2. **The repo is `edoc`, cloned into `~/dms`.** The guide says `dms` for both.
3. **Brevo can block the API by IP address.** This Brevo account has "Authorised IPs" turned on (an earlier session saw Brevo refuse calls from the development PC, see `each_update.md`, 2026-11-13). The server's IP `168.144.112.26` must be added at app.brevo.com/security/authorised_ips, or the restriction switched off. Otherwise production can't send verification, invitation or password-reset emails. Guide 5.2 doesn't mention it.
4. **Two B2 buckets, not one**, with different lifecycle rules (already in the guide; the first bucket was created alone).
5. **Email sender domain** may differ from the site domain (`abateas.app` vs `abateas.com`): see §5.
6. The guide's "Droplet Console" lockout tip may not work once root login is disabled (3.5); editing the firewall rule is the reliable fix.
7. `deploy` has passwordless sudo by design (§3).
8. **Backblaze lifecycle on the replica bucket: never use "Days Till Hide".** That field hides *current* files too, so after N days the live copy of every document would disappear from the replica. The replica bucket needs only "keep prior versions for N days" (delete old versions N days after they are hidden). "Days Till Hide" belongs only on the backups bucket, where every file is a dated backup. Guide 5.4 c has the right setting but doesn't say why; add a warning.
9. **Backblaze free tier is 10 GB** (storage across both buckets). The replica holds every document plus 90 days of deleted ones, so plan to add payment details before the total nears 10 GB, or uploads and the nightly jobs will start failing (Healthchecks would alert).
10. **A one-IP SSH rule fails on networks with several internet lines.** Here the office gateway spreads connections over three public IPs, so SSH worked and timed out at random within the same hour. Guide 2.3 says "your IP"; it should say to sample the IP several times (`curl.exe -s https://api.ipify.org`, ten times) and allow every address that appears, and to ask the network admin for the full list. To tell a firewall block from a dead server: if ports 80/443 answer "refused" while 22 times out, the server is up and the firewall is dropping SSH.
11. **Guide 8.1 is easy to run twice** (here it was, so two invite codes exist). Say "run once", show the expected output (`INSERT 0 1` plus one `Invite code:` line), and add a clean-up step: after the organization is created, deactivate any unused code (`UPDATE signup_invite_code SET active = false WHERE "usedCount" = 0;`), since 8.6 only checks the used one.
12. **Guide 10.1 installs an rclone that no longer works with Backblaze.** `sudo apt install rclone` gives 1.60.1 on Ubuntu 24.04; Backblaze now rejects the login API versions it uses (1–3, only 4 works), so any job using a `b2` rclone remote fails with "not currently supported on API version number 1". Use rclone **1.73.0 or newer** from rclone.org (`https://downloads.rclone.org/<version>/rclone-<version>-linux-amd64.deb`, check the SHA256 against that version's `SHA256SUMS`, then `sudo apt install ./<file>.deb`). Also affects every rclone step in `docs/DMS_Data_Protection_and_Restore.md` (restore from the replica) and `deploy/README.md`. Also add a note to the guide that a failed first replica run pings Healthchecks `/fail`, so an alert email is expected.
13. **Guide 11.1 recommends UptimeRobot's free plan, but its free-plan terms for business use are disputed** (sources conflict; at least one 2026 comparison says non-commercial only). For a company system either check UptimeRobot's current terms or use **DigitalOcean Uptime**, which needs no new vendor and, per DigitalOcean's pricing page, includes one free check (1-minute interval, 4 regions, email alerts). The reboot check (Part 9, check 8) doubles as a test that the monitor alerts.
